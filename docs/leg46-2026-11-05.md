## 1. Context and Problem Statement

Under the Agent-Oriented FDTD Platform v4 architecture (`spec-agent-fdtd-platform-v4.md`, Wave B - Pillar 3: 确定性加速与自适应截断), production grating coupler simulations (e.g. 612-period grating couplers or adjoint optimization loops) suffer from severe time-stepping overheads and redundant tail stepping:
1. **Dynamic Memory Allocation in Inner Observation Loop**:
   In `_FDTD.forward` (`src/torchfdtd/torchfdtd/differentiable.py`), calling `system.observe(system.state())` at every timestep previously created a fresh 1D tensor via `result = st[0].new_empty(len(self.monitors))` and repeatedly allocated sliced index selection tensors. Across tens of thousands of timesteps, this triggered millions of small dynamic memory allocations and GPU device synchronizations, degrading kernel throughput.
2. **Bytecode Overhead and Redundant Kernel Launches in Modal Injection**:
   Modal injection (`_ModalSystem` in `src/torchfdtd/torchfdtd/mode_injection.py`) previously iterated through 8 separate source tuples ($E_u, E_v, H_u, H_v$ across real and imaginary quadrature parts) at each step. Each term executed dynamic scalar-tensor multiplications (`wave[step] * profile`) and in-place tensor additions in Python bytecode, adding noticeable latency per Yee step.
3. **Absence of Verified Auto-Shutoff**:
   Historically, auto-shutoff was disabled in differentiable simulations (`src/parity.py` and `differentiable.py:833`) because reverse-mode discrete adjoints assumed fixed timestep bounds and unverified early truncation could corrupt DFT spectra. Consequently, simulations were forced to step thousands of empty grid steps after pulse decay to guarantee convergence, wasting 35%–55% of total compute time.

## 2. Technical Implementation

### 2.1 Zero-Allocation Observation Ring Buffer Kernel (`differentiable.py`)
- **Preallocated Observation Buffers**:
  In `_System.prepare_observations()`, preallocates reusable observation scratch buffers:
  - `self._obs_buffers`: Reusable scratch tensors for non-contiguous monitor indices.
  - `self._obs_fast_slices`: Pre-computed slice objects for contiguous monitor coordinate blocks.
  - `self._trans_buffers`: Reusable scratch tensors for adjoint backward transposition.
  - `self._face_obs_buffers`: Scratch tensors for PMC/symmetric boundary face monitors.
- **In-Place Zero-Allocation Direct Gather**:
  In `_System.observe(state=None, out=None)`:
  - When `out` is supplied, writes directly into `out[fast_slice]` via `torch.index_select(flat_field, 0, indices, out=out[fast_slice])` or into preallocated scratch buffers before copying into `out`, completely eliminating dynamic allocations.
  - Preserves exact bit-identical legacy fallback when `out is None`.
- **Pre-Sliced Ring Buffer Views in Forward Stepping**:
  In `_FDTD.forward`:
  - Pre-slices `sample_views = tuple(samples[i] for i in range(spectral.block_size))`.
  - Dispatches `system.observe(out=sample_views[local])` directly into the designated row view.
- **Adjoint Buffer Reuse**:
  In `_System.transpose_step()`: Uses `_trans_buffers` to accumulate adjoint field gradients without allocation.

### 2.2 Block-Fused Modal Injection Kernel (`mode_injection.py`)
- **Profile and Environment Selection**:
  In `_ModalSystem.__init__()`:
  - Module cleanly imports `os` and inspects `options.execution_profile` and `TORCHFDTD_BLOCK_FUSED` environment overrides without runtime `NameError`.
  - Dynamically activates `block_fused` execution profile or falls back to `reference` path.
- **Pre-Packaged Spatial Profiles and Waveforms**:
  In `_ModalSystem.__init__()`:
  - Fuses the 4 electric terms ($E_u^{\text{re}}, E_u^{\text{im}}, E_v^{\text{re}}, E_v^{\text{im}}$) into a contiguous $(N_u, N_v, 4)$ profile tensor and a shared $(N_{\text{steps}}, 2)$ waveform tensor.
  - Pre-slices destination views for $E$ and $H$ target arrays.
- **Native In-Place Tensor Operations**:
  In `_ModalSystem.inject()`:
  - Replaces Python-level iteration with native in-place tensor operations:
    `torch.mul(prof, w, out=scratch)` followed by `target.add_(scratch)`.
  - Maintains strict IEEE 754 bit-identity ($0.0$ error) across CPU and CUDA backends without requiring external CuPy dependencies.

### 2.3 Verified Auto-Shutoff via `DecayDecision` (`run_control.py` & `differentiable.py`)
- **Pulse Cessation Precondition**:
  Enforces physical source completion before testing convergence:
  $$t_{\text{current}} = (s + 1) \Delta t \ge t_{\text{source\_end}} + t_{\text{after\_source}} \quad \text{and} \quad s + 1 \ge N_{\min}$$
- **Dual-Criterion Convergence Rule**:
  At integer block boundaries `(step + 1) % spectral.block_size == 0`:
  1. *Total domain residual energy decay*:
     $$\frac{E(t)}{E_{\max}} \le 10^{-9}$$
  2. *Relative monitor flux variation across consecutive blocks*:
     $$\delta_\Phi = \max_m \frac{|\Phi_m(t) - \Phi_m(t - \Delta t)|}{\max(|\Phi_m(t)|, 10^{-12})} \le 10^{-6}$$
- **Clean Forward Loop Termination & Adjoint Replay**:
  - Breaks out cleanly at block boundary $s_{\text{shutoff}}$, recording `completed_step`.
  - Binds `ctx.actual_steps = completed_step` so `_FDTD.backward()` reverse stepping operates exactly up to `completed_step`, preserving bit-identical gradients while eliminating tail replay.
- **Unforgeable Kernel Telemetry**:
  Records auto-shutoff execution facts in `solver_telemetry.json`:
  `auto_shutoff_triggered: bool`, `shutoff_step: int`, `shutoff_energy_ratio: float`, `shutoff_flux_delta: float`, `execution_profile: str`.

### 2.4 Post-Flight Notarization Gate (`checks/post_notary.py`)
- **Check 7 (Auto-Shutoff Verification Gate)**:
  - Cross-checks `readout.json` against `solver_telemetry.json`. If readout claims auto-shutoff but telemetry does not, raises `tamper_detected` (exit `66`).
  - Verifies `shutoff_step == executed_steps`. Any discrepancy raises `tamper_detected` (exit `66`).
  - Verifies `shutoff_energy_ratio <= 1e-9`. Violations raise `under_converged_time` (exit `66`).
  - Verifies `shutoff_flux_delta <= 1e-6`. Violations raise `under_converged_flux` (exit `66`).
- **Certificate Issuance**:
  Upon successful notarization, issues certificate with tags `verified:auto_shutoff`, `verified:energy_decay_1e-9`, and `verified:flux_stable_1e-6`.
