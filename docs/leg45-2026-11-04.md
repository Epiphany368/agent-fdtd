## 1. Context and Problem Statement

Under the Agent-Oriented FDTD Platform v4 architecture (`spec-agent-fdtd-platform-v4.md`, Wave B - Pillar 2: 确定性断点续跑), long-running simulations (e.g. 612-period grating couplers or iterative inverse design loops spanning thousands of timesteps) require robust checkpoint and resume capabilities. Previously:
1. **Lack of Resident Checkpoint/Resume**:
   While TorchFDTD possessed `streamed_restart.py` for streamed out-of-core simulations (`StreamedSimulation`), the primary resident differentiable path (`ModeInjectedPlaneSimulation` $\to$ `_FDTD.forward` in `src/torchfdtd/torchfdtd/differentiable.py`) lacked persistent checkpointing. Any process preemption, crash, or wall-clock timeout resulted in total progress loss.
2. **Deterministic Bit-Identity Requirement**:
   Resuming a simulation from an intermediate step must produce results bit-for-bit identical ($0.0$ error) to an uninterrupted baseline. Any numerical drift in state restoration, DFT phase accumulation, or in-place CUDA pointer invalidation violates reproducibility.
3. **Zero-Trust Pre/Post-Flight Gates**:
   Per the Zero-Trust governance model, an Agent must not be permitted to resume a simulation with a modified structure or altered physical time step ($\varepsilon$ or $dt$). Preflight validation must reject mismatched configurations prior to execution (exit `65`), and postflight notary must cryptographically prove resume provenance (exit `66` on tamper).

## 2. Technical Implementation

### 2.1 Solver Fork: `ResidentRestartJournal` in `src/torchfdtd/torchfdtd/resident_restart.py`
A new dedicated module implementing deterministic, crash-safe checkpointing:
- **Ping-Pong Dual-Slot Architecture**: Alternates checkpoints between `slot_a` and `slot_b`. An atomic pointer `latest-forward.json` published via `_durable_replace` commits the newest valid checkpoint.
- **Fault-Injection & Rollback Resilience**: If a mid-write crash corrupts the latest slot (e.g. truncated `state-*.bin` or invalid SHA-256 header), `load_latest()` transparently catches `RestartRecordDamaged`, records the rollback event in `journal.rollbacks`, and rolls back to the previous intact slot.
- **Contract Invariant Binding (`contract.json`)**: Captures `marker`, `project_canonical_sha256`, `epsilon_sha256`, `epsilon_shape`, `epsilon_dtype`, `dt`, `steps`, `grid_shape`, and `block_size`. Rejects incompatible resumes with explicit diff descriptions.
- **Single-Writer Lock**: Protects journal directory with `owner.json` containing `marker`, `run_id`, `pid`, `host`, and `started`.

### 2.2 Integration into Forward Pass in `src/torchfdtd/torchfdtd/differentiable.py`
- **In-Place Tensor Memory Binding**: Restores Yee fields ($E$, $H$), CPML auxiliary fields ($\psi$), and PMC boundary faces via `target.copy_(source)` without allocating new tensors or re-binding CUDA pointers.
- **DFT Spectral Accumulation**: Restores intermediate DFT complex values `signals`. Exploits DFT linearity across block boundaries:
  $$\text{signals}(0 \to S) = \text{signals}(0 \to s) + \sum_{b=s/B}^{S/B - 1} \text{DFT\_block}(b)$$
- **Continuous Peak Energy Tracking**: Persists and restores `peak_energy` across restarts to guarantee uninterrupted decay ratio computation ($E(T_{\text{end}}) / E_{\max}$).
- **Unforgeable Kernel Telemetry**: Automatically records `resumed_from_step` and `executed_steps = steps - resumed_from_step` into `report['telemetry_kernel']`.

### 2.3 Preflight Gate `checks/pre_resume.py` & Launcher Integration `tools/launch.py`
- **`tools/launch.py`**:
  - Adds `--resume <target>` (and `-r <target>`), resolving either run directory IDs (e.g. `20261104T...`) or explicit journal directory paths.
  - Automatically provisions a new timestamped run directory (`runs/<new_rid>`), recording `resumed_from_journal` and `resumed_from_run_id` in `manifest.json` and `effective.json`.
  - Propagates `TORCHFDTD_RESUME_JOURNAL` and `TORCHFDTD_RESUME_RUN_ID` into subprocess environment.
- **`checks/pre_resume.py`**:
  - Preflight gate executed before simulation driver startup.
  - Validates `contract.json` against current configuration: verifies $\varepsilon$ SHA-256 digest, floating-point $dt$ (relative tolerance $\le 10^{-9}$), and grid shape.
  - Aborts with exit `65` (`failed:preflight=pre_resume.py`) if parameters differ, preventing "running old fields on new structures".

### 2.4 Post-Flight Notary Extension `checks/post_notary.py`
- **Check 1b**: Validates readout `resumed_from_step` against unforgeable kernel telemetry `telemetry['resumed_from_step']`.
- **Check 1c**: Validates readout `executed_steps` matches `telemetry['executed_steps']`.
- **Certificate Issuance**: Embeds `resumed_from_step` into `verification_certificate.json` and attaches tag `'verified:resumed_run'`.

## 3. Test Suite and Verification Evidence

Acceptance test suite `checks/test_leg45_restart_journal.py` implements 10 comprehensive tests:

### 3.1 Unit Tests (5 tests)
- `test_checkpoint_write_and_read_bit_identical`: Bit-identical array serialization and restoration across dual slots ($0.0$ difference).
- `test_ping_pong_dual_slot_rotation`: Verified slot rotation sequence (`slot_a` $\to$ `slot_b` $\to$ `slot_a`).
- `test_damaged_slot_rollback`: Injected corrupted state into `slot_b`; verified clean fallback to `slot_a` with intact state and rollback metadata recorded.
- `test_negative_control_contract_epsilon_mutation`: Mutated $\varepsilon$ hash rejected with `ValueError`.
- `test_negative_control_contract_dt_mutation`: Mutated $dt$ ($1.6 \times 10^{-16}$ vs $1.5 \times 10^{-16}$) rejected with `ValueError`.

### 3.2 Positive Control: 100% Bit-Identity (0.0 Error)
- **Configuration**: 2D Yee grid with dielectric slab ($n = 3.48$), 4000 steps, `block_size = 32`.
- **Baseline (Run A)**: Continuous 0 to 4000 steps.
- **Interrupted & Resumed (Run B)**: Stopped at step 1984 (62 blocks), checkpointed, and resumed to step 4000 from journal.
- **Results**:
  - $|T_A - T_B| == 0.0$ (exact bitwise equality).
  - $|R_A - R_B| == 0.0$ (exact bitwise equality).
  - Field monitor digests `hash_array(sig_a) == hash_array(sig_b2)` match bit-for-bit.
  - Telemetry: `resumed_from_step = 1984`, `executed_steps = 2016`.

### 3.3 Negative Controls via `tools/launch.py` (4 tests)
- **NC 1 (`test_negative_control_1_launch_rejects_epsilon_mutation_exit_65`)**: Mutated $\varepsilon$ rejected by preflight gate with exit `65` (`failed:preflight=pre_resume.py`).
- **NC 2 (`test_negative_control_2_launch_rejects_dt_mutation_exit_65`)**: Mutated $dt$ rejected by preflight gate with exit `65` (`failed:preflight=pre_resume.py`).
- **NC 3 (`test_negative_control_3_launch_recovers_from_corrupted_slot`)**: Truncated slot recovered via fallback to previous intact checkpoint; resumed cleanly with exit `0`, issuing certificate with tag `verified:resumed_run`.
- **NC 4 (`test_negative_control_4_notary_rejects_tampered_resume_steps_exit_66`)**: Driver claiming `resumed_from_step: 0` when kernel telemetry recorded `1984` rejected by post-flight notary with exit `66` (`failed:postflight=tamper_detected`).
