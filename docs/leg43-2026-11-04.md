## 1. Context and Problem Statement

Under the Agent-Oriented FDTD Platform v4 architecture (`spec-agent-fdtd-platform-v4.md`, Wave A), the core governance axiom is **Zero-Trust**:
> "Agent 只有'提议权'，没有'自判权'。一次仿真是否可信由启动器与求解器内核生成的不可伪造遥测指纹 + 强制后置物理公证器决定。"

Prior to LEG 43, `tools/launch.py` possessed a critical security gap:
1. **Blind Trust in Driver Process**: After `proc.wait()`, if the business driver script exited `0`, `launch.py` unconditionally recorded `status = 'completed'` and `exit_code = 0` in `manifest.json` and `runs/ledger.jsonl`.
2. **Fabricated Metrics Vulnerability**: Driver scripts directly authored `readout.json`. An agent or malicious driver could inflate transmission ($T$) from $0.57$ to $0.95$, report false lossless physics (`physics["lossless"] = True`), or even skip the simulation entirely while claiming success.
3. **Absence of Post-Flight Validation**: While pre-flight checks (`checks/pre_*.py`) guarded environment and solver git boundaries (failing with exit `65`), no post-flight validation existed (`checks/post_*.py` was absent).
4. **Physical Invariant Enforcement Gap**: Passivity ($\sum P_{\text{out}} \le P_{\text{in}} + \tau_{\text{pml}}$) and spectral electromagnetic decay ($E(T_{\text{end}}) / E_{\max} \le 10^{-6}$) were not enforced as hard gates.

## 2. Technical Implementation

### 2.1 Solver Kernel Unforgeable Telemetry (`src/torchfdtd`)
Implemented unforgeable telemetry emission directly inside the solver kernel:
- **`src/torchfdtd/torchfdtd/telemetry.py`**:
  - `get_run_dir() -> Optional[Path]`: Checks `os.environ.get("RUN_DIR_ABS")`. If unset or empty, returns `None`. Fast-path execution takes $\sim 0.1\,\mu\text{s}$, guaranteeing 100% bit-identical behavior with zero measurable overhead when running outside the launcher.
  - `hash_array(array: Any) -> str`: Evaluates SHA-256 over contiguous byte buffers of PyTorch tensors or NumPy arrays directly on host/device memory.
  - `emit_telemetry(...) -> Path`: Emits `$RUN_DIR_ABS/solver_telemetry.json` atomically using atomic temporary file replacement (`.json.tmp` -> `.json`).
- **Telemetry Schema (`schema_version: "1.0"`)**:
  - `project_canonical_sha256`: Cryptographic digest of the canonical scene parameterization (`self.plan.plan_hash`).
  - `epsilon_sha256`: SHA-256 hash of the contiguous raw byte buffer of the Yee grid permittivity array.
  - `is_lossless`: Evaluated directly from tensor memory ($\text{Im}(\varepsilon) = 0$, no absorber conductivity, and no lossy ADE oscillators $\gamma = 0$).
  - `executed_steps`: Actual step counter completed by the GPU/CPU kernel.
  - `resumed_from_step`: Initial starting step (`0` for initial launch; checkpoint step in Wave B).
  - `energy_decay_ratio`: Evaluates electromagnetic energy ratio $E(T_{\text{end}}) / E_{\max}$ across periodic sampling points.
  - `monitors`: Keyed by monitor ID, mapping to `{"flux": float_or_list, "digest": str}` where `digest` is the SHA-256 of the raw accumulated fields.
- **Kernel Hooks**:
  - `Simulation._run` (`src/torchfdtd/torchfdtd/solver.py`): Enables `StateDiagnostics(g)` when `run_dir` is present; evaluates monitor fluxes, field hashes, and decay ratio; emits telemetry atomically before returning `Result`.
  - `_FDTD.forward` (`src/torchfdtd/torchfdtd/differentiable.py`): Samples electromagnetic energy periodically ($N/200$ interval) into `report['telemetry_kernel']` with zero tensor allocations in the inner loop.
  - `DifferentiableSimulation._run` (`src/torchfdtd/torchfdtd/differentiable.py`): Emits telemetry for time-history differentiable simulations.
  - `DifferentiablePlaneSimulation._planes` (`src/torchfdtd/torchfdtd/adjoint_planes.py`): Extracts surface-integrated Poynting fluxes and accumulated plane field digests for all declared plane monitors; emits telemetry atomically upon completion.

### 2.2 Launcher Post-Flight Notary Integration (`tools/launch.py`)
In `tools/launch.py`, integrated post-flight notary execution immediately after `proc.wait()`:
```python
        # Post-flight notary gate (LEG 43)
        if status == 'completed':
            with (run / 'stdout.log').open('a') as log:
                for check in sorted((ROOT / 'checks').glob('post_*.py')):
                    result = subprocess.run([sys.executable, '-B', str(check), str(run)],
                                            env=env, stdout=subprocess.PIPE,
                                            stderr=subprocess.STDOUT, text=True)
                    log.write(result.stdout)
                    log.flush()
                    print(result.stdout, end='', flush=True)
                    if result.returncode != 0:
                        rc = 66
                        status = 'failed:postflight=tamper_detected'
                        message = f'[run.sh] postflight failed: {check.name} (exit={result.returncode})'
                        log.write(message + '\n')
                        print(message, flush=True)
                        break
```
- **Exit 66 Negative Control Enforcement**:
  If any post-flight notary check fails:
  - Return code is overridden to **`66`**.
  - Manifest status is overridden to **`failed:postflight=tamper_detected`**.
  - Recorded in `manifest.json`, `run/status`, and tracked `runs/ledger.jsonl`.
  - Process exits with code `66`.
- **Preservation of Driver Finding Exit Codes**:
  If a driver script exits non-zero (e.g. pre-declared stop condition `exit 53` `stopped:non-monotone`), `status` is `failed:exit=53` (not `completed`). The post-flight notary is not invoked, and the driver's exit code `53` is strictly preserved.

### 2.3 Post-Flight Notary Engine (`checks/post_notary.py`)
Implemented `checks/post_notary.py` enforcing:
1. **Schema Check**: Validates `schema_version == "1.0"`.
2. **Audit Exemption**: Non-simulation audit tasks (`config.kind == 'audit'` with `simulation_executed == False`) issue an `audit_only` certificate with exit `0`.
3. **Mandatory Artifacts**: Refuses missing or corrupted `solver_telemetry.json` or `readout.json` with exit `66`.
4. **Step Consistency**: Verifies $|s_{\text{telemetry}} - s_{\text{readout}}| == 0$.
5. **Permittivity Consistency**: Verifies declared `epsilon_sha256` matches kernel telemetry.
6. **Lossless Truthfulness**: Rejects runs where `readout` claims `lossless: true` but kernel telemetry reports `is_lossless: false`.
7. **Monitor Flux Consistency & Bidirectional Alias Mapping**:
   Implements bidirectional mapping:
   ```python
   alias_map = {
       'box-right': ['T', 'transmission', 'trans', 'far', 'box-right'],
       'box-left': ['R', 'reflection', 'refl', 'near', 'box-left'],
       'transmission': ['T', 'transmission', 'trans', 'far', 'box-right'],
       'reflection': ['R', 'reflection', 'refl', 'near', 'box-left'],
       'scattered': ['S', 'scattered', 'scat'],
       'top': ['top', 'up'],
       'bottom': ['bottom', 'down'],
   }
   ```
   Compares monitor fluxes against reported fluxes within dimensionless tolerance $\tau_{\text{flux}} = 10^{-5}$.
8. **Universal Passivity Gate**: If `is_lossless == True`, enforces $\sum P_{\text{out}} \le 1.0 + \tau_{\text{pml}}$ ($\tau_{\text{pml}} = 10^{-5}$). Any power creation triggers immediate refusal with exit `66`.
9. **Spectral Energy Decay Gate**: Enforces $E(T_{\text{end}}) / E_{\max} \le 10^{-6}$ (`decay_floor`). Under-converged simulations trigger refusal with exit `66` (`under_converged_time`).
10. **Verification Certificate**:
    Upon passing all gates, issues `$RUN_DIR/verification_certificate.json` containing digests (`telemetry_sha256`, `readout_sha256`, `config_sha256`, `project_canonical_sha256`, `epsilon_sha256`), metrics, `verified: true`, and verification tags.
